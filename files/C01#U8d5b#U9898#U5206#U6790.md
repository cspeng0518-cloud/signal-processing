# C01 多类型电磁信号感知赛题分析

> 来源：《C01 多类型电磁信号感知赛题任务详情描述文档.pdf》（共 9 页）

## 一、赛题背景与目标

**背景**：复杂电磁环境下雷达、通信等多类型信号高度交叠，传统单一体制、单一任务感知手段难以完成多类型信号的分类识别与参数估计，无法满足多任务一体化、国产算力适配与实时信息获取等需求。

**核心目标**：构建**电磁通用感知基座模型**，从模型算法能力和国产化适配落地两方面进行能力评估，结合感知任务的国产化算力平台适配成效遴选优势团队。

## 二、三大任务

| 任务 | 内容 | 关键点 |
|------|------|--------|
| **任务1：时-频特征编码与融合** | 基于信号时域动态信息和频域谱特征，设计时-频双流特征编码架构，构建跨域融合交互模块 | 特征在通道、空间或注意力层面的动态对齐与融合 |
| **任务2：基座模型多任务适配** | 设计系统化的基座模型多任务适配架构，具备不同任务语义映射统一表征能力 | 挖掘任务间潜在关联，实现任务间协同增效 |
| **任务3：国产化迁移适配与效率提升** | 打通"算法-框架-算力"链路，消除对 CUDA 生态的强依赖 | 异构算力适配与算子迁移，降低计算开销与推理时延，控制精度损失，实现国产算力平台稳定部署 |

### 任务难点

1. 设计高效时-频特征编码融合机制，增强基础模型对复杂信号的理解和建模能力
2. 具备不同任务语义映射统一表征能力，挖掘任务间潜在关联性，实现任务间协同增效
3. 在国产化平台上开展异构算力适配与算子迁移，对模型架构进行优化，降低计算开销与推理时延

## 三、数据集

### 数据集概述

- **数据构成**：通信信号 + 雷达信号，采用同相正交（IQ）双通道数值序列表示
- **采样长度**：512 点或 1024 点
- **规模**：约 **120 万条**标准化训练数据
- **覆盖范围**：通信与雷达多种体制与波形

### 三类测试项

| 测试项 | 类别数 | 示例 |
|--------|--------|------|
| 体制类型识别 | 8 类 | WiFi、Bluetooth、5G、Radar 等 |
| 调制类型识别 | 23 类 | OOK、BPSK、16QAM、LFM、Barker Code 等 |
| 物理域参数估计 | 7 个关键参数 | 码元速率、带宽、脉冲宽度、载频、PRI、时延、脉冲数等 |

- 分类标签以规定字符串形式标注；物理参数以连续或计数数值形式记录。

### 数据存储格式

统一存储于 **Apache Parquet** 格式文件，按样本逐行存储：

- 每条记录包含：测试项类型 `task`、唯一标识 `sample_id`、二维 I/Q 时序数据 `iq`
- 训练集额外包含对应测试项标签及**有效性标识**字段
- 测试集仅提供模型推理所需输入字段（不含真实标签）

### 输入/输出样例

**输入样例**（Parquet 格式）：

```json
{
  "task": "modulation",
  "sample_id": "sample_000001",
  "iq": [[0.12, -0.08], [0.15, 0.03], ...]
}
```

**输出样例**（JSONL 格式，每行一条记录，包含 `task`、`sample_id`、`prediction` 三个字段）：

```json
{
  "task": "modulation",
  "sample_id": "sample_000001",
  "prediction": "BPSK"
}
```

参数估计任务的 prediction 为字典：

```json
{
  "task": "parameter",
  "sample_id": "sample_000003",
  "prediction": {
    "symbol_rate": 1000.0,
    "bandwidth": 1500.0,
    "frequency_shift": 20.0,
    "pulse_width": 0.000002,
    "pri": 0.000008,
    "time_delay": 0.000001,
    "number_of_pulses": 4.0
  }
}
```

> 注意：参数预测须采用数据规定的原始单位，不输出有效性掩码，由主办方根据独立保存的有效性标记选取适用参数评分。

## 四、解题约束条件（关键红线）

- 模型参数量 **≤ 1B**
- 基座模型在不同任务间**共用基座模型权重超过 80%**
- 不能根据不同任务分别训练多个基座模型
- 不能进行多个小模型集成
- 不能通过外挂知识库进行模型能力增强
- 不限制模型架构：可在开源基础模型上构建，也可从零设计新架构

## 五、成果交付边界

1. **算法模型**：多维信号融合表征模型算法、训练推理部署包（任务源代码、模型权重及配置文件、Docker 镜像和部署说明、训练数据及来源说明、训练及适配优化的推理日志）
2. **技术方案**：技术创新性设计方案、关键技术说明、实验结果分析

## 六、解题环境与格式规范

- **编程语言**：Python（主办方以 Python 接口形式复核模型权重与训练代码）
- **开源框架**：不限训练框架；Docker 镜像须为 Linux 架构、预装推理全部依赖、不得声明匿名 VOLUME、不得依赖运行时下载
- **运行环境基线**：Ubuntu 22.04 LTS、CUDA 12.X、PyTorch

## 七、评测与评分规则

### 评测方式

- **评测程序自动评估**：对提交模型在对应测试项上自动评估打分
- **专家评审**：对提交技术方案进行线下评审打分

**评测程序公平性**："统一数据、统一程序、统一指标、统一规则"，测试集不向参赛队伍开放，评测过程保留提交记录、运行日志和评价结果，可追溯。

### 初赛评分规则（自动打分，总分 100）

| 评分项 | 分值 | 说明 |
|--------|------|------|
| 信号体制特征识别 | 30 | 结合复测情况，准确率一致时考虑宏平均召回率 |
| 信号调制类型识别 | 30 | 结合复测情况，准确率一致时考虑宏平均召回率 |
| 物理域参数估计 | 40 | 结合复测情况，根据预测结果样本方差计算得出 |

初赛原始总分：Sₒ = Σ αᵢSᵢ，结合成果复测情况得出最终成绩 S𝒻。

### 复赛评分规则（自动打分 70% + 专家评审 30%）

**（1）评测程序自动打分**

| 评分项 | 分值 | 说明 |
|--------|------|------|
| 信号体制特征识别 | 20 | 结合复测情况，准确率一致时考虑宏平均召回率 |
| 信号调制类型识别 | 20 | 结合复测情况，准确率一致时考虑宏平均召回率 |
| 物理域参数估计 | 30 | 结合复测情况，准确率一致时考虑宏平均召回率 |
| 计算效率提升度 | 30 | 结合复测情况，按推理时延排名打分 |

**（2）专家现场评审打分**

| 评分项 | 分值 | 评分说明 |
|--------|------|----------|
| 技术路线 | 15 | 技术突破完成度、逻辑清晰程度、内容完整程度、格式工整程度等 |
| 技术创新性 | 20 | 思路的前沿突破情况，前瞻性、突破性的观点和思考 |
| 模型能力 | 20 | 线下复现情况、计算效率提升程度、模型性能 |
| 工程实现 | 30 | 工程实现可行性、落地实施效果、风险预测与应对措施 |
| 成果应用价值 | 15 | 赋能业务领域及经济、科研、军事、社会价值 |

### 评分指标计算方式

- **准确率**：Aᵢ = 预测正确的样本数 / 该任务全部样本数，任务得分 Sᵢ = 分值 × Aᵢ
- **精准度**：Pᵢ = 1 / (1 + 样本均方根误差 / 固定参考尺度)，任务得分 Sᵢ = 分值 × Pᵢ
- **计算效率提升度**：S₄ = 分值 × (N − Rₜ) / (N − 1)，其中 Rₜ 为推理时延排名，N 为复赛参赛团队数量

## 八、难点与策略建议

1. **时-频融合**：双流编码（如 1D-CNN 时域分支 + FFT/STFT 频域分支）+ 注意力对齐融合是主流方案，对应任务 1
2. **多任务统一**：建议共享 backbone + 任务特定 head 的多任务学习架构（如 MoE / task prompts），需满足 80% 权重共用约束，对应任务 2
3. **国产化适配**：复赛 30 分给了推理效率，推理时延优化（量化、剪枝、算子替换为国产平台算子）是拉开差距的关键，对应任务 3
4. **评分导向**：初赛参数估计占 40 分最重，7 个物理参数的回归精度需重点投入；准确率并列时比宏平均召回率，**类别均衡**很重要（小类不能放弃）

**总分结构洞察**：初赛三大项要求均衡发展；复赛加入效率分后，"精度-时延"权衡能力成为核心竞争点。
